# Changed-input review

The complete workflow still fetches all ten sources, writes a new run, freezes inputs,
archives prior bytes and recomputes Stages 01–07. No live rerun is needed to test this
behavior: `test_adaptability.py` uses explicit local fixture transports in temporary
repositories. Completed repository snapshots and evidence are never edited.

EVIDENCE has **no fixed row count**: zero, ten, eleven or more source rows are retained.
Required headers, unique nonempty record IDs, exact system joins and matching HTML/CSV
representations remain mandatory. Additional columns (including supplied record versions)
and actual row locators are preserved. SYSTEMS still requires the eight expected case
systems; CALENDAR retains its existing eight-action contract. Duplicate IDs, broken joins,
missing headers, representation disagreements and scope changes stop processing with
retained capture/failure diagnostics. No new source identity checks are bypassed.

`reviewed-case.json` is explicit interpretation configuration derived from the prior
reviewed case, with its basis snapshot ID/hash. It is not a company source, a substitute
for retrieval, independent corroboration or Legal approval. Each new workflow freezes
its bytes and traces it through Stage 01 and Stage 04. The engine pins this configuration
version/hash: editing a template cannot silently authorize new legal conclusions. A
new interpretation basis needs an explicit code/configuration revision and review/tests.

The engine compares **current captured** material register values and authored context
against that reviewed basis. It no longer requires prose fragments or aborts because
operating facts have changed. Heading/layout whitespace, inventory names, owner routing,
newer versions and report timestamps do not themselves change statutory applicability.
A change to use, role labels, exposed groups, output types, notices, human review or
reported evidence status produces a scoped review blocker. Inventory labels alone never
establish provider/deployer status. New, changed, missing or reassigned evidence records
also require review: free-text claims are not automatically interpreted as new legal
triggers. Reassignment affects both the former and current system.

Blockers distinguish changed facts, missing facts/context, additional/changed evidence,
invalid evidence states, conflicting reports, policy changes and uncertain context dates.
Duplicate context sections and ambiguous dates are not arbitrarily resolved. Prose changes
are valid new source content; an unreviewed meaning is **unresolved**, not a malformed
source. Whitespace is normalized for comparison only; actual source bytes remain unchanged.

Affected findings are recomputed as unresolved (or conflicting where the current register
reports a conflict), with current record IDs and explicit reasons. A changed per-system
use/context conservatively withholds that system's eight interpretations and role/transition
assessments. Shared role/date uncertainty can affect all systems. Policy-only uncertainty
changes policy findings and review requests without inventing a new statutory trigger.
Unchanged systems retain supported scoped findings. Missing evidence and a newly reported
`complete` state never become compliance, approval or automatic conflict closure.

Within the recognized current-product timing statement, valid market-entry date changes
are parsed and recompute the limited provider Article 50(2) transition. Unknown product
subjects, missing/invalid dates or changed timing meaning withhold that timing conclusion;
unchanged deployer disclosure findings are not deferred. The assigned review date remains
26 August 2026, separate from reported observation/authoring and actual retrieval times.

Stage 05 records blockers and removes affected no-impact conclusions. Stage 06 adds explicit
undated owner-review actions, carries questions to Legal and Operations, and replaces stale
acceptance wording for affected proposals. Source calendar IDs, owners, dates and versions
remain verbatim. All requests are pending/unsent; no new due date or approval is invented.
Stage 07 uses current evidence states/timing, lists blockers and binds all new requests to
actual draft bytes. Technical draft validation can pass while publication remains blocked.

Limits: this is a conservative reviewed-case interpreter, not a natural-language legal
classifier. A harmless wording change beyond whitespace can require review; new operating
semantics are withheld rather than guessed. Hidden tabs, missing live POLICY access,
unverified manual provenance and authenticated feedback handling remain unresolved limits.
